Frontend sản phẩm & giao diện

Họ tên:   Hạn bàn giao:

Mục tiêu: hoàn thiện trải nghiệm xem/chọn giày, UI đăng nhập/đăng ký và admin sản phẩm. Tận dụng giao diện đã có, không dựng lại toàn bộ từ đầu.

Công việc phụ trách

  1. Review trang chủ: navbar, hero, sản phẩm phổ biến, bộ sưu tập, banner và footer.
  2. Hoàn thiện danh sách giày: card, giá VND, tìm kiếm, lọc danh mục/thương hiệu/giá và sắp xếp.
  3. Hoàn thiện chi tiết: đổi màu/kiểu cập nhật đúng ảnh/giá/kho; chọn size, số lượng; khóa size hết hàng.
  4. Phụ trách giao diện đăng nhập/đăng ký, menu tài khoản, lỗi form và trạng thái đang xử lý. Người 2 phụ trách xác thực/API.
  5. Phụ trách UI admin sản phẩm: tạo/sửa/ẩn mẫu giày, biến thể, giá, tồn kho và danh mục; dùng API của Người 2.
  6. Giữ theme thống nhất; kiểm tra mobile/desktop, loading/empty/error, focus bàn phím và thao tác đóng dialog.

Phạm vi file và phối hợp

frontend/components/shop.tsx, auth-dialog.tsx, store-info.tsx, store-icons.tsx, product-image.ts, frontend/app/globals.css và tài liệu UI.

Tách phần admin sản phẩm khỏi account-panel.tsx ở mốc tích hợp đầu tiên, cùng Người 3 chốt ranh giới component. Thư mục/route mới chỉ tạo sau khi thống nhất; không coi là phần đã có.

Sản phẩm bàn giao

  • PR có danh sách màn hình đã hoàn thiện và ảnh desktop/mobile.
  • Bảng các trạng thái đã kiểm tra; danh sách lỗi còn lại nếu có.
  • Hướng dẫn dùng giao diện admin sản phẩm và nội dung báo cáo của phần mình.

Điều kiện nghiệm thu

  • Chọn đúng biến thể, giá và size; không tự chọn size thay người mua.
  • Tìm/lọc đúng; trạng thái không có kết quả và lỗi API dễ hiểu.
  • Admin thêm/sửa/ẩn sản phẩm qua API; khách không được hiển thị thao tác admin.
  • Không tràn ngang ở 320–1440px; form, menu, dialog thao tác được.

Phần báo cáo

Thiết kế giao diện, luồng xem/chọn giày, responsive, UI tài khoản và quản lý sản phẩm; ảnh minh chứng.

Phần demo

Trang chủ → tìm giày → đổi biến thể → chọn size; mở admin sản phẩm bằng tài khoản admin.

NestJS API, Convex & xác thực

Họ tên:   Hạn bàn giao:

Mục tiêu: chịu trách nhiệm toàn bộ quy tắc dữ liệu và quyền truy cập ở server. API admin thuộc Người 2; UI admin sản phẩm/đơn thuộc Người 1/3.

Công việc phụ trách

  1. Review schema 7 bảng, index và liên kết sản phẩm–biến thể–size–giỏ–đơn. Chỉ duy trì Convex trong backend.
  2. Hoàn thiện API NestJS cho sản phẩm, danh mục, giỏ, đặt/hủy đơn, cập nhật trạng thái và quản trị.
  3. Review đăng ký/đăng nhập email–mật khẩu, băm scrypt, JWT/cookie HttpOnly, thu hồi phiên và lỗi hết hạn.
  4. Kiểm tra quyền customer/admin và chủ sở hữu ngay trong Convex; không tin role, userId hoặc giá do trình duyệt gửi.
  5. Bảo đảm checkout đọc giá từ database, kiểm tra/trừ kho và tạo đơn trong một transaction; hủy pending hoàn kho đúng một lần.
  6. Duy trì seed nhất quán; chuẩn bị dữ liệu demo phù hợp ảnh/màu/kiểu. Nếu có dữ liệu cũ cần giữ, lập backup/migration trước khi đổi schema.
  7. Viết tài liệu API, bổ sung tests cho nghiệp vụ thay đổi và hỗ trợ Người 4 cấu hình xác thực production.

Phạm vi file và phối hợp

backend/src/auth/, src/shop/, src/convex/, src/http-policy.ts, backend/convex/ và backend/scripts/.

Người 2 chủ trì logic dùng chung ở frontend/lib/, components/providers.tsx và proxy app/api/[...path]/route.ts; phối hợp Người 1/3, để Người 4 kiểm tra môi trường. Không sửa binding _generated/ bằng tay.

Sản phẩm bàn giao

  • Sơ đồ dữ liệu; docs/api.md ghi endpoint, dữ liệu, quyền, lỗi và ví dụ JSON không chứa secret.
  • Tests nghiệp vụ/quyền; hướng dẫn seed, cấp admin và xử lý môi trường.
  • Danh sách thay đổi schema và hướng xử lý dữ liệu cũ nếu có.

Điều kiện nghiệm thu

  • Không trả password hash/token cho frontend dưới dạng dữ liệu công khai.
  • Khách bị chặn API admin và đơn/giỏ của người khác.
  • Đặt/hủy đơn đúng giá và kho; lỗi giữa chừng không để ghi dữ liệu dở dang.
  • Tests, lint, build và kiểm tra kiểu Convex đạt.

Báo cáo & demo: kiến trúc API, sơ đồ 7 bảng, xác thực/phân quyền, transaction; minh chứng truy cập hợp lệ/bị từ chối và dữ liệu trước–sau đặt/hủy đơn.

Giỏ hàng, checkout & đơn hàng

Họ tên:   Hạn bàn giao:

Mục tiêu: khách mua được hàng bằng COD, theo dõi/hủy được đơn; admin quản lý tiến trình đơn. Giao diện gọi API NestJS, không ghi trực tiếp Convex.

Công việc phụ trách

  1. Hoàn thiện giỏ theo tài khoản: đúng biến thể/size, đổi số lượng, xóa dòng, hiển thị tổng tiền và giỏ trống.
  2. Hoàn thiện form checkout: họ tên, số điện thoại, địa chỉ; kiểm tra dữ liệu và thông báo lỗi theo phản hồi server.
  3. Hiển thị xử lý/thành công/thất bại; hạn chế gửi lặp thao tác trong lúc chờ API; làm mới giỏ và đơn sau thay đổi.
  4. Hoàn thiện lịch sử và thông tin đơn: sản phẩm, size, số lượng, giá lúc mua, tổng tiền, giao hàng và trạng thái.
  5. Cho khách hủy đơn pending; giải thích rõ trường hợp không được hủy hoặc tồn kho đã thay đổi.
  6. Phụ trách UI admin đơn hàng: danh sách và chuyển pending → confirmed → shipping → delivered; hủy theo quyền cho phép.
  7. Phối hợp Người 1 ở thao tác thêm giỏ; phối hợp Người 2 khi thay đổi dữ liệu, quyền hoặc nghiệp vụ; hỗ trợ Người 4 chạy kịch bản tích hợp.

Phạm vi file và phối hợp

frontend/components/account-panel.tsx và các component giỏ/checkout/đơn được tách sau khi chốt. Dùng frontend/lib/shop-client.ts, shop-api.ts, types.ts theo hợp đồng của Người 2.

Người 3 chủ trì tách cart/checkout/orders/admin orders; Người 1 nhận phần admin sản phẩm. Hai người thống nhất props/export trước khi sửa chung file lớn.

Sản phẩm bàn giao

  • Luồng mua COD hoàn chỉnh qua API; ảnh/video hoặc biên bản chạy thử.
  • Bảng test giỏ, checkout, lỗi tồn kho, lịch sử/hủy đơn và admin đơn.
  • Nội dung báo cáo và kịch bản demo phần giỏ/đơn của mình.

Điều kiện nghiệm thu

  • Giỏ đúng tài khoản; không hiển thị dữ liệu người trước sau đăng xuất/đổi tài khoản.
  • Đổi/xóa số lượng hoạt động; không cho mua vượt tồn kho.
  • Checkout thành công tạo đơn đúng, làm trống giỏ; thất bại báo lỗi rõ ràng.
  • Khách chỉ hủy đơn hợp lệ; admin chỉ chuyển trạng thái theo thứ tự.

Phần báo cáo

Luồng mua hàng, form/validation, quản lý trạng thái UI, lịch sử đơn và tích hợp API.

Phần demo

Thêm giỏ → thay số lượng → đặt COD → xem đơn → hủy pending; minh họa admin xử lý đơn khác.

Tích hợp, Cloud deploy & kiểm thử

Họ tên:   Hạn bàn giao:

Mục tiêu: cả 4 thành viên chạy được cùng phiên bản và bản deploy hoạt động đầy đủ. Không chỉ triển khai giao diện; cần kiểm tra cả API NestJS và Convex.

Công việc phụ trách

  1. Quản lý tích hợp GitHub, nhánh/PR và phiên bản dùng để demo; kiểm tra không đưa file môi trường hoặc khóa vào commit.
  2. Thiết lập CI kiểm tra cả frontend và backend: tests, lint, build; bổ sung HTTP e2e backend.
  3. Chốt phương án triển khai frontend trên Vercel, triển khai NestJS và deployment Convex production phù hợp điều kiện nhóm.
  4. Cấu hình URL Nest ở frontend, origin frontend ở Nest, URL/deployment Convex và bộ khóa JWT/secret production cùng Người 2.
  5. Kiểm tra HTTPS, cookie, đăng nhập/đăng xuất, quyền admin/customer và các request đi hết frontend → Nest → Convex.
  6. Điều phối kiểm thử bản deploy trên mobile/desktop và hai tài khoản; ghi lỗi, người sửa, kết quả kiểm tra lại.
  7. Tạo checklist triển khai/khôi phục, ghi lại lệnh và cấu hình theo tên biến; không đưa giá trị secret vào báo cáo.
  8. Tổng hợp tài liệu từ 3 người còn lại, chuẩn hóa báo cáo/slide và tổ chức diễn tập.

Phạm vi file và phối hợp

Cấu hình CI/deploy, README.md, frontend/.env.example, backend/env.example, tài liệu vận hành và bằng chứng kiểm thử. Phối hợp Người 2 khi thay đổi proxy, cookie, khóa hoặc deployment.

Sản phẩm bàn giao

  • URL frontend/Nest, định danh Convex deployment và commit dùng demo.
  • Hướng dẫn một thành viên khác có thể chạy/deploy lại; danh sách tên biến môi trường.
  • Biên bản kiểm thử trên bản deploy, checklist rollback và báo cáo/slide đã tổng hợp.

Điều kiện nghiệm thu

  • Cả ba tầng chạy liên thông; lỗi API không bị nhầm là lỗi giao diện.
  • Tài khoản customer/admin và luồng COD hoạt động trên bản deploy.
  • Không dùng chung private key/secret giữa dev và production theo mặc định.
  • Có log kết quả kiểm thử, commit, tài liệu và phương án quay lại bản ổn định.

Báo cáo & demo: quy trình GitHub → build/deploy, sơ đồ Cloud, cấu hình theo tên biến, URL bản chạy và bằng chứng request đi qua Nest đến Convex. Không trình chiếu secret.

Quy tắc bàn giao và review

  1. Mỗi issue có mã, người làm, người review, hạn, phạm vi file và điều kiện hoàn thành.
  2. Mỗi PR có mô tả hành vi thay đổi, lệnh kiểm tra/kết quả; UI có ảnh, API có ví dụ và lỗi/quyền.

  6. Chỉ đánh dấu “hoàn thành” sau review và kiểm thử đúng môi trường. “Có code” không đồng nghĩa “đã nghiệm thu Cloud”.

CloudKicks06 · RUNBOOK & XÁC NHẬN NHÓM

Chạy cùng phiên bản, bàn giao rõ ràng

Chạy local sau khi đã cấu hình môi trường

TerminalThư mụcLệnh giữ chạy
1backend/npm.cmd run convex:dev
2backend/npm.cmd run start:dev
3frontend/npm.cmd run dev

Cài dependencies bằng npm.cmd ci trong từng thư mục. Lần đầu ở backend chạy npm.cmd run auth:setup; seed chỉ chạy cho database chưa có sản phẩm. Mở http://localhost:3000, Nest mặc định ở port 3001. Không chạy Convex từ frontend.

Kiểm tra trước bàn giao

# frontend/ npm.cmd test npm.cmd run lint npm.cmd run build
# backend/ npm.cmd test npm.cmd run test:e2e npm.cmd run lint npm.cmd run build

Những điểm cấu hình phải kiểm tra

  • Frontend: BACKEND_URL. Backend: CONVEX_DEPLOYMENT, CONVEX_URL, PORT, FRONTEND_ORIGIN.
  • Khóa xác thực: JWT_PRIVATE_KEY_BASE64, NEST_JWKS_BASE64, NEST_AUTH_SECRET; Người 2/4 kiểm tra sự tương ứng, không ghi giá trị vào tài liệu.
  • Đăng ký tài khoản mới bằng email/mật khẩu. Cấp admin có kiểm soát bằng internal mutation users:setAdmin với email; tải lại trang sau khi cấp quyền.
  • Tài khoản Clerk/deployment frontend cũ không tự chuyển sang tài khoản mới. Không xóa dữ liệu cũ hoặc tắt schema validation để vượt lỗi đồng bộ.
